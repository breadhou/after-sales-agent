# 转交 Codex：交接物准备

**目标**：让 Codex 打开这两个仓库时，能拿到与当前会话等价的项目上下文与工作约定。

**范围**：`after-sales-agent` + `supermall` 两个仓库一起（用户 2026-09-22 选定）。

**为什么需要这份文档**：本节列出的三条事实都是**实测**得出的，且其中两条是**静默失效**——不检查就不会发现。交接物若建立在「Codex 能读到我们的文档」这个未经验证的假设上，失败方式与 K-1、K-26 同族。

---

## 一、三个已核实的事实

### 事实 1：`after-sales-agent` 没有任何指令文件

```
.git  .gitignore  .idea  README.md  docs/
```

无 `AGENTS.md`、无 `CLAUDE.md`、无 `.claude/`。`git remote -v` 为空、只有 `main` 一个分支。

**后果**：Codex 打开本仓库，拿到的项目上下文是**零**。目前「怎么在这个仓库里干活」的约定只存在于两处——`README.md`，以及当前会话的记忆目录（Codex 读不到）。

### 事实 2：`supermall/AGENTS.md` 会被 Codex 静默截断

| | |
|---|---|
| 文件大小 | **51,908 字节** |
| Codex 默认上限 | **32,768 字节**（`project_doc_max_bytes`，源码 `PROJECT_DOC_MAX_BYTES: usize = 32 * 1024;`） |
| 超出行为 | **静默丢弃，无任何提示**（TUI、`/stats`、`codex exec`、IDE 扩展均不报） |
| 实际可见 | **前 412 行 / 共 549 行**（实测） |

来源：[openai/codex#7138](https://github.com/openai/codex/issues/7138)、[openai/codex#13386](https://github.com/openai/codex/issues/13386)。对比：Claude Code 在 `CLAUDE.md` 过大时会明确警告，Codex 不会。

本机 `~/.codex/config.toml` **未覆盖**该值，故默认生效；`~/.codex/AGENTS.md` 为 0 字节（空文件会被跳过）。

**被截断掉的正好是一处交叉引用**：

| 内容 | 行 | Codex 可见 |
|---|---|---|
| 「本地测试环境启动」 | 47–110 | ✅ |
| `refund` 索引检查清单（K-7 的成果） | 368–370 | ✅ |
| **「待办」第 2 项**（启动流程做成项目 skill） | 522–537 | ❌ |
| **「相关项目」**（指向 after-sales-agent） | 545–549 | ❌ |

而 `after-sales-agent/README.md:88` 恰恰写着「见 supermall 仓库 `AGENTS.md` 的『待办』第 2 项」——**这个指针在 Codex 下指向一段它看不见的文字**。同一句里的「本地测试环境启动」却可见，所以是半截失效，不会显式报错。

### 事实 3：`supermall` 的两份指令文件已经漂移

| | `CLAUDE.md` | `AGENTS.md` |
|---|---|---|
| 大小 | 34,545 字节 | 51,908 字节 |
| 是否分发 | **否**（`.gitignore:41` 的 `/CLAUDE.md` 排除） | **是** |
| Claude Code 读 | ✅（默认二选一，有 CLAUDE.md 时不读 AGENTS.md） | ❌ |
| Codex 读 | ❌ | ✅ |

标题级差异（节名措辞已分叉）：「关键架构约定」vs「架构与编码约定」、「测试与验证基线」vs「测试覆盖基线」、阶段六标题的「与单机验证／万级持续压测待环境恢复」vs「和集成验证／持续压测待验证」。

**最要紧的一处**：`CLAUDE.md` 的「待办」写着「原有各项均已处理完毕」，`AGENTS.md` 的「待办」列着两条未完成。

于是本机 Claude 与 Codex（以及任何新 clone）读的是**两套已经分叉的指令**。这是 K-29 那个模式的又一次现身——「同一事实的多个副本，各自漂移」——只不过这次漂移的是**指令文件本身**。

### 附带事实：`AGENTS.md` 可以一份文件同时服务两个 agent

Claude Code 自 v2.1.277 起原生读 `AGENTS.md`，条件是**项目路径上没有 `CLAUDE.md`**（默认 `claude-md-or-agents-md` 是「二选一」，不是合并）。
来源：[Claude Code memory 文档](https://code.claude.com/docs/en/memory)。

| 仓库 | Claude 读 | Codex 读 |
|---|---|---|
| `after-sales-agent`（两个文件都没有） | ← **一份 `AGENTS.md`，两边都读** → | |
| `supermall`（两个文件都有） | `CLAUDE.md` only | `AGENTS.md` only |

> ⚠️ **要写进 `after-sales-agent/AGENTS.md` 的一个坑**：将来若有人在该仓库加一个 `CLAUDE.md`，Claude 会**停止读 `AGENTS.md`**（默认二选一）。一句话能防一次静默失效。

## 二、决策（用户 2026-09-22 裁定）

| D | 「执行计划」依赖 superpowers 子技能 | **不改三份计划**，在 `AGENTS.md` 里写等价说明 |
| E | 只在记忆里的约定 | 落地进 `AGENTS.md`（最主要是 PowerShell 下 `-D` 必须加引号的坑） |
| F | 新发现的问题 | 按项目纪律追加进 `docs/known-issues.md` |

**B 为什么不选另外两个**：

- 抬高本机 `project_doc_max_bytes`——**只对本机生效**，配置不在仓库里，换机器即复原。属于本项目一直在批评的「靠约定维护的一致性」（K-1、K-2、K-11 同源）。
- 只把「待办」「相关项目」前移——改动最小，但下次追加内容又会把它顶出去，且打乱文件的时间顺序。**治标，且会反复发作。**

**副作用需知情**：指令文件本来就不该兼作进度日志。移出后 `AGENTS.md` 从 51 KB 降到约 17 KB，对模型也是减负。
